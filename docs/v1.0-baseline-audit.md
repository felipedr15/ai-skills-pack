## CI Issues

- CI uses floating `python-version: "3.x"`, which can move under the project without review.
- CI currently runs both `validate-all.py` and unit tests, but `validate-all.py` itself also runs unit tests, creating duplicate effort.
- Workflow triggers are broad (`push`, `pull_request`) rather than explicitly scoped to pushes to `main` and pull requests into `main`.
- No concurrency cancellation is configured.
- No manual `workflow_dispatch` trigger is configured.
- CI does not explicitly run `git diff --check`.
- CI does not clearly separate repository validation, tests, MCP smoke, and release readiness.

## Documentation Inconsistencies

- `README.md` states that the repository does not currently expose a unified AI OS CLI module for memory commands, but `WORKFLOW.md` documents Phase 7 unified CLI commands.
- `scripts/ai-os.py status` reports `Release ready: True` even when `release-check` reports release blocked.
- `WORKFLOW.md` has duplicate numbering in Phase 8.
- The current README Quick Start remains generic and does not document a v1.0 fresh-clone path.
- Canonical Markdown multi-device setup documentation is missing.

## Known Technical Debt

- v0.9.0 release notes list these known limitations:
  - `scripts/profile/` shadows Python's standard-library `profile` module.
  - Approval expiry is not implemented.
  - Malformed approval-store records may trigger a Phase 8 `KeyError`.
  - Live `.ai-os/sessions/` data is excluded from deterministic work-activity artifacts.
  - `windowDays` is descriptive metadata, not a wall-clock filter.
  - `--force-refresh` snapshots current curated content but does not regenerate it.
  - Sanitization is regex-based and still requires human review.
  - Richer role/team/expertise graph relationships are deferred.
  - Evidence-resolution status is not shown through MCP or dashboard.

## Recommended Remediation

1. Regenerate deterministic artifacts using the official generation scripts and re-run staleness checks.
2. Harden test temp-directory behavior on Windows and Python 3.14, or document and pin the supported Python range if 3.14 is not intended for v1.0.
3. Make `status` use real health checks and report `UNKNOWN` or `FAIL` instead of optimistic readiness.
4. Harden approval-store parsing so malformed records produce controlled validation errors without normal CLI tracebacks.
5. Add portable MCP configuration documentation and avoid canonical absolute local paths.
6. Update CI to explicit `main` push and PR triggers, add `workflow_dispatch`, add concurrency, pin supported Python, run `git diff --check`, and make validation jobs easier to interpret.
7. Update repository ownership references to `felipedr15/ai-skills-pack`, preserving only intentional history.
8. Create formal v1.0 acceptance criteria before claiming release readiness.
