# AI OS v1.0 Technical Debt

Date: 2026-08-26

This document classifies known v0.9.0 limitations and baseline audit findings for the v1.0 hardening milestone.

## Critical For v1.0

### Malformed approval-store records

Status: fixed

Risk: malformed records in `.ai-os/approvals/approvals.json` could trigger unsafe direct-key lookups, including the pre-existing `KeyError` noted in v0.9.0.

Resolution:

- Approval reads now validate that the store root is a list.
- Approval ID generation ignores malformed records instead of crashing.
- Approval list, lookup, update, reject, and approval checks use safe access.
- Malformed records are preserved for validation visibility rather than silently deleted.
- Orchestration validation avoids direct `target` assumptions when collecting approved memory-suggestion approvals.

Tests:

- `test_malformed_approval_record_does_not_crash_read_operations`
- `test_request_approval_preserves_malformed_records_and_generates_id`

Validation:

- `python -m pytest tests\test_orchestration_approvals.py tests\test_release.py -q` passed: 72 passed.

### Status command reports release readiness from file existence only

Status: fixed

Risk: `python scripts/ai-os.py status` reported `Release ready: True` while `release-check` and `validate-all` failed. This could mislead a release operator.

Resolution:

- Status now runs existing generated-artifact freshness checks.
- Status exposes `generationChecks` and `summary` in JSON.
- Human-readable status reports subsystem results and `Overall: NOT READY` when generated artifacts are stale.
- Existing JSON fields such as `version`, `artifacts`, `dashboard`, `mcp`, and `releaseReady` remain compatible.

Tests:

- `test_status_release_ready_requires_current_generated_artifacts`
- Updated CLI status assertion for the new `Overall:` summary.

## Recommended For v1.0

### Stale generated artifacts

Status: pending Step 5 / final regeneration

Reason: Multiple generated artifacts are stale at baseline. They should be regenerated after source and documentation changes are complete to avoid repeated churn.

### CI trigger and Python-version hardening

Status: pending Step 3

Reason: CI uses floating Python `3.x`, broad event triggers, and lacks concurrency and `git diff --check`.

### Portable MCP setup

Status: pending Step 2

Reason: Existing MCP smoke tests pass, but setup examples still include absolute paths and canonical Markdown multi-device setup documentation is missing.

### Repository ownership references

Status: pending Step 4

Reason: Source docs and Git remote still reference `frojas15/ai-skills-pack`.

### Sanitization language

Status: pending documentation update

Reason: Sanitization is regex-based and useful, but documentation must continue to state that human review remains required for sensitive data.

## Deferred After v1.0

### Approval expiration

Status: deferred

Reason: The current approval model already fails closed for non-`approved` statuses, including a future `expired` status. Adding wall-clock expiration would require policy decisions for retention, display, and audit semantics. v1.0 keeps historical approvals intact and does not silently expire or delete them.

### `scripts/profile/` shadows Python standard-library `profile`

Status: deferred

Reason: Renaming the package would touch a broad import surface across CLI, tests, dashboard, MCP, and generated artifacts. The current issue is documented, and no active runtime bug was isolated during the baseline audit.

### Live `.ai-os/sessions/` excluded from committed work activity

Status: no longer considered a defect

Reason: This is an intentional deterministic-generation boundary. Local runtime state remains excluded from committed generated artifacts so output stays portable across machines.

### `windowDays` is descriptive metadata

Status: deferred

Reason: Implementing a wall-clock activity filter changes semantics and may make generated artifacts time-dependent. v1.0 should preserve deterministic generation.

### Richer role/team/expertise graph relationships

Status: deferred

Reason: Current graph exposure intentionally avoids leaking detailed profile content through general traversal. Broader professional graph semantics need a privacy review before implementation.

### Evidence-resolution status in MCP/dashboard

Status: deferred

Reason: Useful, but not required to preserve core release gates. It should be added only with careful summary-only exposure.

## Environment Issue Tracked From Baseline

Running tests inside the managed sandbox on Windows/Python 3.14.4 caused widespread `PermissionError` failures for temporary directories under `AppData\Local\Temp` and test-created `pytest-cache-files-*` directories. The same targeted test set passed outside the sandbox. This is tracked as an execution-environment issue, not as proof that the affected application modules are broken.
