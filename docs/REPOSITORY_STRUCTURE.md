# Repository structure

[Start here](../README.md) · [Placement rules](CONTENT_PLACEMENT_RULES.md)

AI OS keeps entry points and tool configuration at the repository root. Human documentation about this repository lives in `docs/`. Paths in registries and integration settings are contracts; update consumers and validators before relocating them.

| Location | Purpose | Source of truth / placement note |
| --- | --- | --- |
| Root (`README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, `VERSION`) | Entry, policies, history and version | Edit directly. Root `AGENTS.md`, `CLAUDE.md`, `agents.json`, `prompts.json`, `skills.json`, `Directory.Packages.props`, and bootstrap scripts remain here for integration compatibility. |
| `docs/` | Repo architecture, process, governance, setup, project roadmap, releases, and human guides | Edit source docs here; `docs/reference/` contains human reference handouts. |
| `.github/` | GitHub workflows and Copilot instructions | GitHub integration files; retain paths. |
| `.agent/` | Agent skill definitions and integration settings | Skill `SKILL.md` front matter is authoritative for the generated skill registry. |
| `.kiro/` | Kiro integration settings | Retain tool expected paths. |
| `agents/` and `agents.json` | Role instructions and machine readable registry | Role text lives in `agents/`; `agents.json` is the manually maintained registry of IDs, paths, and metadata. Keep both synchronized. |
| `prompts/` and `prompts.json` | Prompt text and machine readable registry | Prompt text lives in `prompts/`; `prompts.json` is the manually maintained registry of IDs, paths, and metadata. Keep both synchronized. |
| `skills/` and `skills.json` | Skill supporting content and legacy registry | The skill definitions are in `.agent/skills/`; root `skills.json` is a compatibility registry, not the generated source of truth. |
| `knowledge/` | Stable, reusable subject knowledge | Curated knowledge; not live project status. |
| `memory/` | Evolving project/session/decision context | Source records and `memory/registry.json` are authoritative; generated indexes are derived. |
| `references/` | Supporting reference material used by contributors or the system | See `references/README.md`; repo instructions belong in `docs/`. |
| `standards/`, `specs/`, `schemas/` | Rules, feature requirements, and machine readable data contracts | Keep each type separate. |
| `templates/`, `examples/` | Reusable starting points and completed examples | Template project `ARCHITECTURE.md` and `ROADMAP.md` stay inside each template. `examples/mcp/` is an example. |
| `scripts/`, `tests/` | Commands and automated verification | Edit source code and tests here. |
| `config/`, `profile/` | Tool configuration examples and profile context | Keep credentials and personal local settings out of git. |
| `generated/` | Derived registries, indexes, graph, dashboard | Generated by commands in `generated/README.md`; do not hand edit. Committed outputs must be regenerated after source changes if checks require them. |

## First contribution

Read the [README](../README.md), [placement rules](CONTENT_PLACEMENT_RULES.md), and [contribution guide](../CONTRIBUTING.md). Use a root bootstrap script if needed. Run the validation commands in the README after edits.
