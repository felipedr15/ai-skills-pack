# AI OS v1.0 Acceptance Criteria

AI OS is v1.0-ready only when the gates below are verified from actual commands and review evidence.

For the actual final PASS/FAIL results recorded against these gates, see
[docs/v1.0-final-acceptance.md](v1.0-final-acceptance.md).

## Repository

- Git working tree is clean after generation.
- No unintended machine-specific absolute paths are committed.
- No legacy repository owner references remain except intentional history.
- No secrets, tokens, credentials, `.env`, private keys, or local config are committed.
- Internal links validate.

## Core Validation

- `python scripts/ai-os.py doctor` passes or reports only documented environment warnings.
- `python scripts/ai-os.py status` reports `Overall: HEALTHY`.
- `python scripts/ai-os.py build --check` passes.
- `python scripts/validate-all.py` passes.
- `python -m unittest discover -s tests -v` passes in CI.
- `python -m pytest` passes in a supported local environment.
- `python scripts/ai-os.py release-check` passes.
- `git diff --check` passes.

## Memory

- Memory index generation and check pass.
- Memory security validation passes.
- Archive and promote flows remain approval-gated.
- Malformed approval records do not crash normal approval CLI operations.
- No automatic memory promotion exists.

## Knowledge

- Knowledge graph generation, check, and validation pass.
- Semantic discovery generation, check, and validation pass.
- Unresolved references are either fixed or documented.
- Search, related entities, traversal, and path lookup work through CLI/MCP paths.

## Orchestration

Verify:

- `python scripts/ai-os.py classify "Fix the login bug"`
- `python scripts/ai-os.py plan "Fix the login bug" --explain`
- `python scripts/ai-os.py session start "Fix the login bug"`
- `python scripts/ai-os.py session validate <id> --name unit-tests --status pass`
- `python scripts/ai-os.py session complete <id>`
- `python scripts/ai-os.py approval list --status pending`
- `python scripts/ai-os.py memory-suggestions list --status pending`
- `python scripts/ai-os.py knowledge-health`
- `python scripts/ai-os.py knowledge-gaps`

Approval gates must remain explicit and human-controlled.

## Professional Context

Verify:

- `python scripts/ai-os.py profile list`
- `python scripts/ai-os.py profile show`
- Profile switching requires an approved `profile-switch` approval.
- Expertise retrieval exposes evidence summaries only.
- Work activity generation remains deterministic.
- Sanitization remains deterministic and documented as requiring human review.
- Profile data is not automatically inferred or promoted into memory.

## MCP

- MCP starts from a clean configuration.
- `python scripts/ai-os.py mcp check` passes.
- MCP startup works when the repository is cloned to a different directory.
- `AI_OS_HOME` is optional and falls back safely.
- MCP exposes no approval-mutating, profile-mutating, arbitrary shell, Git, credential, or network tools.

## Dashboard

- `python scripts/dashboard-build.py` completes.
- `python scripts/dashboard-validate.py` passes.
- Major sections appear in generated dashboard data and HTML.
- Dashboard remains local-first, static/generated, read-only, and free of browser-side private network calls unless explicitly designed.

## Fresh Clone

Validate from a fresh clone:

```powershell
git clone https://github.com/felipedr15/ai-skills-pack.git
cd ai-skills-pack
python --version
python scripts/ai-os.py doctor
python scripts/ai-os.py build --check
python scripts/ai-os.py validate
python scripts/ai-os.py mcp check
python scripts/ai-os.py dashboard
python scripts/ai-os.py classify "Prepare a documentation update"
```

If generated files are stale in the clone, run:

```powershell
python scripts/ai-os.py build
git diff --check
```

Review and commit regenerated artifacts only when the diff is expected.
