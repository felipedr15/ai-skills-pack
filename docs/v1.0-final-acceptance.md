## Knowledge Graph Warnings

`validate-knowledge-graph.py` reports two nonblocking warning categories. Both were reviewed
individually rather than assumed passing.

### Unresolved references (3, down from 9)

6 of the original 9 were a real bug, now fixed: `.agent/skills/build/` (the "build" skill
taxonomy category) collided with a generic "skip build-output directories" exclusion rule shared
by `scripts/knowledge_graph/utils.py`, `scripts/semantic_discovery/utils.py`,
`scripts/index-repository.py`, and `scripts/ai_os_service/permissions.py` (MCP path confinement).
This silently excluded 7 files under `.agent/skills/build/` -- the `creator`, `frontend`,
`performance-optimization`, `vercel-agent`, `vercel-react`, and `web-design-guidelines`
`SKILL.md` files, plus the `build` category's own index `SKILL.md` -- from the repository index
(378 -> 392 tracked files at the time of the fix), the knowledge graph (14 -> 21 skill nodes),
semantic discovery search, and MCP `get_repository_file` access. Fixed by carving `.agent/skills/` out of the generic directory-name
exclusion in all four modules; skill files there are explicitly-tracked source content, not build
output, regardless of which taxonomy category folder they live under.

The remaining 3 are intentional and do not need correction:

- `README.md` -> `generated/README.md` and `README.md` -> `generated/memory-index.md`: the graph
  deliberately does not create nodes for every generated Markdown summary (only a small,
  explicitly-listed set of `generated/*.json` registries get supplemental document nodes) --
  `generated/` is derived output, never source of truth, consistent with `README.md`'s and
  `ARCHITECTURE.md`'s statements. A human-readable link from the top-level README to a generated
  summary is expected; it just won't resolve to its own graph node.
- The Phase 9 spec pointer file under `.kiro/specs/` (see `tests/test_spec_hygiene.py`) links to
  its canonical directory under `specs/phase-9-professional-context/`, which is a directory, not a
  file. The graph only creates nodes for individual files.

### Isolated nodes (51, unchanged)

Reviewed the full list. All 51 are `document` nodes (49), one `memory` node, and one `profile`
node with no other repository document currently linking to or mentioning them: JSON Schema files
(`schemas/*.schema.json`), Phase 8 workflow definitions (`knowledge/workflows/*.json`),
project-memory and specification templates (`templates/project-memory/*.md`,
`templates/specifications/*.md`, `templates/memory/*.md`), GitHub Copilot instruction files
(`.github/instructions/*.md`), a couple of generated/config JSON files, and one memory/profile
record without cross-links yet. This is expected under the documented design: the graph's
"Relationship discovery is conservative and uses explicit links, wiki links, metadata, and curated
text cues" (`ARCHITECTURE.md`); templates and schemas are consumed by copy/reference, not by
markdown links from other repository documents, so they are correctly isolated rather than
incorrectly missing edges. No correction needed.
